# Example: an agent answers a question through Relate's MCP server

Run 14 Nov 2026. A fresh Claude subagent, told nothing about the project except [agent/PROMPT.md](../../agent/PROMPT.md), queried
`data/prometheus.rl` only through `scripts/mcp_query.py` (Relate's own `relate serve --mcp stdio --read-only`). Its tool calls were audited afterwards:
it read the brief once and ran its queries in two calls, nothing else. Five of its numbers were then re-run independently and matched
(10 and 20 bridge fields, 19 shared prerequisites, co-classified since 1977, 499 and 751 patents through 2005, 18 and 24 partners).

**The question:** "As of 2005, why might the fields G06E and G06M combine? What is the evidence for and against, and what actually happened afterwards?"

## The agent's answer (verbatim)

**Short answer:** By 2005, G06E (optical computing devices) and G06M (counting mechanisms) had a lot of overlap around them but had not combined. They still had not combined by the end of the data in 2025.

**Evidence as of 2005**
- *For:* 10 bridge fields were already combined with both, including G06F, G06V, G06T, G01N, G01R, H03K and H03M. 19 fields were shared prerequisites that both built on, such as G06F, G06K, G01R and G02B. Their genome vectors are almost identical (score 0.998). By 2005 G06E had 18 combination partners and G06M had 24.
- *Against:* the pair was first co-classified in 1977, so after 28 years it had still not reached the 3-patent threshold. That makes it a stalled pair, not a new one. Both fields were small: 499 G06E patents and 751 G06M patents through 2005, with only 120 and 194 in 1996–2005.

**After 2005:** the pair never combined. The edge query returned no row. The bridge fields doubled to 20. G06E's partners grew to 30 and G06M's to 37. Both stayed small, with 286 and 449 more patents.

**Caveats:** the bridge and prerequisite counts are a ranking, not a probability, and the genome score probably uses data through 2025, so it is not a pure 2005 view.

### Queries

```
MATCH (f:Field) WHERE f.code IN ['G06E','G06M'] RETURN f.code, f.title, f.firstYear, f.nPatents
MATCH (a:Field {code:'G06E'})-[r:COMBINED_WITH]-(b:Field {code:'G06M'}) RETURN r.firstYear, r.count
MATCH (a:Field {code:'G06E'})-[r:CO_CLASSIFIED]-(b:Field {code:'G06M'}) RETURN r.firstYear
MATCH (a:Field {code:'G06E'})-[r1:COMBINED_WITH]-(c:Field)-[r2:COMBINED_WITH]-(b:Field {code:'G06M'}) WHERE r1.firstYear <= 2005 AND r2.firstYear <= 2005 RETURN c.code, c.title, r1.firstYear, r2.firstYear ORDER BY c.code
MATCH (a:Field {code:'G06E'})-[r1:BUILDS_ON]->(c:Field)<-[r2:BUILDS_ON]-(b:Field {code:'G06M'}) WHERE r1.firstYear <= 2005 AND r2.firstYear <= 2005 RETURN c.code, c.title, r1.firstYear, r2.firstYear
MATCH (y:FieldYear) WHERE y.code IN ['G06E','G06M'] AND y.year <= 2005 RETURN y.code, sum(y.n) AS through2005
MATCH (m:Meta) RETURN m.source, m.slice, m.dataEndYear, m.minPairPatents
MATCH (a:Field {code:'G06E'})-[r1:COMBINED_WITH]-(c:Field)-[r2:COMBINED_WITH]-(b:Field {code:'G06M'}) RETURN sum(CASE WHEN r1.firstYear <= 2005 AND r2.firstYear <= 2005 THEN 1 ELSE 0 END) AS bridges2005, count(c) AS bridges2025
MATCH (a:Field)-[r:COMBINED_WITH]-(b:Field) WHERE a.code IN ['G06E','G06M'] RETURN a.code, sum(CASE WHEN r.firstYear <= 2005 THEN 1 ELSE 0 END) AS partners2005, count(b) AS partners2025
MATCH (y:FieldYear) WHERE y.code IN ['G06E','G06M'] AND y.year > 2005 RETURN y.code, sum(y.n) AS after2005
MATCH (f:Field {code:'G06E'}) CALL db.index.vector.queryNodes('field_genome', 400, f.genome) YIELD node, score WITH node, score WHERE node.code = 'G06M' RETURN node.code, score
MATCH (y:FieldYear) WHERE y.code IN ['G06E','G06M'] AND y.year >= 1996 AND y.year <= 2005 RETURN y.code, sum(y.n) AS n1996_2005
```

## Why this example is interesting

G06E × G06M is the pair the graph ranks first under "Beyond size" in 2005. The agent found, without being told, that it had been co-classified since 1977 and never
reached the threshold, and that it still had not combined by 2025: a high-ranked pair that did not come true, explained by the graph itself.
It also noticed on its own that the genome score is computed from all years, so it is not a clean 2005 view. That is correct: the stored genome uses data through 2025.
